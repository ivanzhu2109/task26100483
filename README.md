# vmplanner

边缘集群批量 VM 放置规划器（Go 库）。在固定快照上做整批准入与放置规划：
不执行 VM 操作，不做持久化，不处理并发提交。

- 整批全有或全无：1–20 台 VM 必须全部放得下才接纳。
- 可接纳时返回**全局最优**方案：最小化 U = 所有健康节点放置后
  CPU 利用率与 RAM 利用率的最大值（分母为各节点总容量）。
- 目标值以精确有理数（`Ratio{Num, Den}`）比较与返回，不用浮点。
- 核心求解为仓库内实现的精确分支定界，未委托任何外部求解器。

## 放置规则

- 单台 VM 的 CPU、RAM 分别不得超过目标节点**总容量**的 80%
  （精确判定：`demand*5 <= total*4`）。
- 节点原有占用 + 新分配需求，两种资源分别不得超过总容量；VM 不可拆分。
- 只有健康节点接纳新 VM；不健康节点也不计入 U。

## API

```go
res, err := vmplanner.Plan(nodes, requests)
// res.Feasible=false 表示整批无解；否则 res.Placement（vmID->nodeID）
// 与 res.Objective（精确最优 U）有效。

chk, err := vmplanner.Check(nodes, requests, placement)
// 校验调用者自造方案：完整性、80% 配额、容量、健康节点；
// 并用同一定义计算 U（不判断最优性）。
```

输入约束：2–4 个节点；CPU 为整数核（≤64/节点）；RAM 为整数 MiB
（≤524288/节点）；每批 1–20 台 VM，标识唯一，需求为正整数。

## 运行测试

```sh
go test ./...                              # 全部单元测试 + 穷举对照 + 压力测试
go test -run TestExhaustiveCrossCheck -v   # 152 组小实例 vs 独立穷举参考实现

```

压力样例每例断言：耗时 < 10s、额外内存 < 256 MiB，并用 `Check`
核验所有返回方案。实测每例均在毫秒级完成。

## 实现要点

- 请求按"可选节点数少者优先、需求大者优先"排序。
- 分支定界剪枝：单调利用率下界、总量聚合下界、最大剩余 VM 下界、
  同构节点去重、状态转置表（只影响剪枝，不影响完备性）。
- 贪心仅用于产生初始上界；可行性与最优性完全由精确搜索决定，
  绝不把贪心失败或搜索开销当作无解。
